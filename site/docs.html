Docs

Laravel Wiki adds a team wiki to an existing Laravel app. Everything here also works in the live demo, except editing.

Install

You need Laravel 12 or 13 and PHP 8.3 or newer. Any database Laravel supports will do.

composer require ruvelo/laravel-wiki
php artisan migrate

Open /wiki in your app and sign in to write the first page. The migration adds three tables: wiki_pages, wiki_revisions and wiki_links.

Who can edit

By default anyone can read the wiki, and anyone signed in can create, edit, delete and restore pages. To choose who can edit, define a wiki-edit gate, for example in your AppServiceProvider:

use Illuminate\Support\Facades\Gate;

Gate::define('wiki-edit', fn ($user) => $user->is_admin);

To keep the whole wiki behind a login, add auth to the middleware every wiki route uses:

// config/wiki.php
'middleware' => ['web', 'auth'],

Editing always requires a signed-in user who passes the gate. The edit buttons only appear for people who can use them.

Writing pages

Pages are written in Markdown, GitHub-style: headings, bold and italic, lists, task lists, tables, fenced code blocks and links.

Linking pages

Put a page title in double brackets to link to it. Add a label after a pipe to change the link text:

Read the [[Deploy guide]] first.
Ask [[On-call rota|whoever is on call]].

Links to pages that don't exist yet show in red. For editors they open the new-page form with the title filled in; other readers see a "no page here yet" page.

Each page lists the pages that link to it under What links here.

Table of contents

Put [TOC] on a line of its own and it becomes a table of contents built from the page's headings.

Safety

Raw HTML in a page is shown as text, not run, and javascript: links are removed. Someone with edit access can't make the page run scripts in a reader's browser.

History

Every save creates a revision. A page's History lists them with author, time and summary. Open one to see what changed, line by line, and put that version back with Restore this version. Restoring is a save like any other, so it can be undone too.

If someone saves a page while you're editing it, your save is refused rather than overwriting their work. Your text stays in the editor so you can merge it by hand.

Changing the look

The wiki ships with its own layout so it looks finished out of the box. To change it, publish the views:

php artisan vendor:publish --tag=wiki-views

They land in resources/views/vendor/wiki. Every page extends layout.blade.php, so replacing that one file puts the wiki inside your app's own layout. Pages fill a title and a content section, and there's a wiki-head stack for extra tags in <head>.

To keep the layout and only change colours, override the CSS variables at the top of it, such as --wiki-accent for links and buttons and --wiki-new for links to missing pages.

PHP API

Everything the UI does is available from your code through Ruvelo\Wiki\Wiki. Every save goes through the same path as the editor: it records a revision, re-indexes links and fires events.

use Ruvelo\Wiki\Wiki;

// Create or update (an identical save records nothing)
$page = Wiki::write('Release notes', $markdown, 'v2.0 notes', $user);

// Create only: throws PageAlreadyExists if the title is taken
Wiki::create('Onboarding', '- [ ] Get a laptop');

Wiki::find('Release notes');          // by title or slug, or null
Wiki::search('deploy')->limit(5)->get();
Wiki::render('**Markdown** with [[links]]');

Pages are Eloquent models, so the usual tools work too:

$page->html();                 // rendered, safe HTML
$page->plainText();            // for previews and search snippets
$page->revisions;              // newest first
$page->backlinks()->get();     // pages that link here
$page->outgoingLinks();        // slugs this page links to

// Save, refusing if someone else saved since revision 41
$page->commit($title, $body, 'Fix typo', $user, basedOn: 41);

Exceptions

All extend Ruvelo\Wiki\Exceptions\WikiException: EditConflict (with expectedRevision and currentRevision), PageAlreadyExists (with the existing page) and InvalidTitle.

Events

PageSaved fires after every create, edit and restore, with $page and $revision; $event->wasCreated() tells a new page from an edit. PageDeleted fires after a page and its history are removed.

Event::listen(PageSaved::class, function (PageSaved $event) {
    Slack::post("{$event->page->title} was updated: {$event->revision->summary}");
});

JSON API

A REST API for pages and revisions, off by default. Turn it on with WIKI_API=true. It's served under /api/wiki and expects Sanctum tokens; set wiki.api.middleware to use another guard. Reading needs a valid token; writing also needs the wiki-edit gate.

RequestDoes
GET /pages?q=List pages, or search them. Paginated, per_page up to 100.
GET /pages/{slug}One page with body, html, revision, links and backlinks.
POST /pagesCreate. 201, or 409 if the title is taken.
PATCH /pages/{slug}Update title and/or body. Send base_revision to get a 409 instead of overwriting a newer save.
DELETE /pages/{slug}Delete the page and its history. 204.
GET /pages/{slug}/revisionsHistory, newest first.
GET /pages/{slug}/revisions/{id}One revision with its body.
POST /pages/{slug}/revisions/{id}/restorePut that version back.
 
curl -X PATCH https://example.com/api/wiki/pages/deploy-guide \
  -H "Authorization: Bearer $TOKEN" -H "Accept: application/json" \
  -d body="Ship on Tuesdays." -d base_revision=41

Import and export

Bring in a folder of Markdown files: an Obsidian vault, a docs/ folder or a GitHub wiki checkout. [[links]], including [[Page#Section]] and [[Page|label]], work as-is.

php artisan wiki:import ~/notes --user=1 --dry-run
php artisan wiki:import ~/notes --user=1

Each file's title comes from title: front matter, else a leading # Heading, else the file name. Importing again only saves files that changed, so it's safe to run on a schedule. Hidden folders such as .obsidian and .git are skipped.

php artisan wiki:export storage/wiki          # one {slug}.md per page
php artisan wiki:export storage/wiki --force  # overwrite existing files

Exported files carry their title in front matter, so wiki:import reads them back unchanged. Commit the folder to Git for a plain-text backup.

Extending Markdown

The renderer is league/commonmark with GitHub-flavoured Markdown. Add any CommonMark extension through the config, or customise the environment in code:

// config/wiki.php
'markdown' => [
    'extensions' => [FootnoteExtension::class],
    'options' => ['footnote' => ['backref_symbol' => '↩']],
],

// or in a service provider's boot()
Wiki::extendMarkdown(fn (Environment $env) => $env->addExtension(new MentionExtension));

Raw HTML stays escaped unless you change html_input. Only do that if every editor is trusted.

Testing your app

A factory makes real pages, with a first revision and indexed links, for your own tests:

use Ruvelo\Wiki\Models\Page;

Page::factory()->titled('Deploy guide')->create();
Page::factory()->linkingTo('Deploy guide', 'On-call rota')->create();

Page addresses never contain an underscore, so the /_/ pages can't clash with a page's address.

Questions

What happens to links when I rename a page?

Nothing breaks. A page keeps the address it was created with, and existing [[Old title]] links keep pointing at it.

Can I search across a big wiki?

Search uses your database's LIKE, which is fine for thousands of pages. For more, listen for PageSaved and feed a search engine such as Meilisearch.

composer install
